## 確かめ済み（2026-11 時点）

- macOS での起動（`${TMPDIR}` の使用、`open` でのブラウザ起動の分岐、vendor の配信）
- SQL実行まわり：`node dev/test-sql.js` で、パスワードがプロンプトに混ざらないこと・参照以外のSQLを弾くこと・DBに届かないときは実行しないことを自動確認
- 実機のPostgreSQL（SSHトンネル越し）に `claude -p` から psql で接続し、結果が返ること
- `claude -p` は、その人が普段 Claude Code に与えている許可をそのまま使う（`--allowedTools` を渡さなくても、許可済みのコマンドは実行できる）
- 道具を指定しない `/api/runsql` が、本物のClaudeと本物のPostgreSQLで通ること（CLAUDE.md に接続方法を書いたプロジェクトで確認。`{columns, rows}` と vega-lite が返った）
- 別オリジンのページからの操作を断ること（攻撃を書いて実演 → 合言葉の導入後は不成立）
- `--allowedTools "Bash(psql:*)"` のように絞ると、psql は通り `ls` は `permission_denials` に入って拒否される
- `claude -p --resume <id> --fork-session` で、メインの文脈を引き継いだ回答が返る。メインの会話記録は変わらない
- 続きの質問は同じ分岐セッションに積める
- スキル内の `${CLAUDE_SESSION_ID}` と `${CLAUDE_SKILL_DIR}` は置き換わる
- `/understand` → アプリで返す → 「終わった」で、メインが本筋を直し、作業フォルダを片付けるところまで
- `/understand diff` のコードレビュー、`/understand このPRを理解したい` の説明文書作成（実際の Claude で）
- 費用の目安：分岐の初回 約1ドル、2回目以降 約0.3ドル（キャッシュが効く）、PRの説明文書 約0.8ドル。モデルや会話の長さで大きく変わる

## 既知の課題

- 付箋の回答の中の `pre` を横スクロールしたまま、ホイールでボードを動かすと、`pre` の中身が横にずれて見える（ホイールが付箋内のスクロールに使われるため）
- 複数行にまたがる選択は、出どころのマーカーが最初の1行（の先頭40文字）にしか付かない
- 付箋どうしが重なったときの自動配置は簡易的（下にずらすだけ）。「整列」で直る
- 「本筋への影響：」の行が、回答本文と強調表示の両方に出て二重に見える
- 同じ付箋に連続で質問すると、前の回答を待つ（並行しない）。別の付箋なら並行できる
- 分岐の初回は会話全体を読み込むので、メインの会話が長いほど遅く、高くなる

## アイデア（まだ手をつけていない）

- 名前を決める（理解だけでなくレビューにも使えるので `/understand` は少し狭い）
- PRモードで、`gh pr view --comments` のレビューコメントも説明文書に取り込む
- 付箋を「理解できた」で閉じる操作（たたむとは別に、理解の進み具合が見える）
- 本筋の段落ごとに「まだ付箋がない＝読み飛ばしたかも」を薄く示す
- メモ付箋の内容も、返す文の下書きに使う（今は選べば使われるが、目立たない）
- 依頼文モードで、PR以外（「認証の流れを理解したい」など）の説明文書のガイドを `pr-guide.md` と同じように用意する
